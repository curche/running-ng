## 1. Starting point

Investigating the `pplacer_testsuite` regression flagged in
`experiments/compactor-comparison/plots/turing-2026-07-01-Wed-230036/results.md`
finding #3: all three non-stock runtimes (`ocaml-auto-compact`, `socaml`,
`socaml-auto-compact`) were ~19-20% slower than `ocaml-5.5` on this benchmark,
with identical RSS and zero compactions — i.e. not a compaction-triggering
issue. Original ask: does `running-ng` have a dry-run mode, and what are the
exact commands run per runtime for this benchmark?

## 2. Found dry-run mode

`running-ng` supports `-d`/`--dry-run` (`src/running/__main__.py:22`,
`running.suite.set_dry_run`). In dry-run, `Benchmark.run()`
(`src/running/benchmark.py:383-390`) prints the fully-expanded command line to
stderr instead of executing — no subprocess, no perf/olly attach.

Built a scratch isolated config restricting `macrobenchmarks_compactor_4way.yml`
to just `pplacer_testsuite`, dry-ran it, and extracted the base commands:

```
OCAMLRUNPARAM="e=25,d=2" <binary>-ocaml-5.5 5
OCAMLRUNPARAM="e=25,d=2" <binary>-ocaml-auto-compact 5
OCAMLRUNPARAM="e=25,d=2" <binary>-socaml 5
OCAMLRUNPARAM="e=25,d=2" <binary>-socaml-auto-compact 5
```

(`re-25` → `e=25` ring size, `md-2` → `d=2` min domains.)

Noted caveat: `perf_grp1` (the `PerfAndOllyAttach` modifier) doesn't appear in
argv — `perf stat` and `olly gc-stats` are attached post-fork via
SIGSTOP/SIGCONT on the PID (`src/running/benchmark.py:136-296`), with
`OCAML_RUNTIME_EVENTS_START=1` / `OCAML_RUNTIME_EVENTS_DIR=<tmp>` in the env.

Verified all four opam switches and pre-built binaries from the original
experiment still exist (`opam switch list`,
`/home/curche/git/macro-benches/benchmarks/pplacer/`).

## 3. Ran it for real

User asked to actually execute the reproduction. Config-merge gotcha hit
along the way: `Configuration.combine()` merges dict values with `.update()`
(`src/running/config.py:372-394`), so a top-level `benchmarks:` key only
*replaces* the `macro-pplacer` entry — every other suite from
`macro_base.yml` survives untouched. Had to move `benchmarks:` under
`overrides:` instead (uses `Configuration.override()`, plain assignment, no
merge) to actually isolate the run to just `pplacer_testsuite`.

Confirmed the patched `olly` (branch `count-auto-compactions` in
`/home/curche/git/runtime_events_tools`, needed to count `EV_COMPACT` in
addition to `EV_EXPLICIT_GC_COMPACT`) was already built and put it on `PATH`.

Ran for real: run id `turing-2026-07-13-Mon-230928`, 3 invocations × 4
runtimes. Parsed the `olly_*.json` NDJSON sidecars (one JSON line per
invocation) for `wall_time`, `max_rss_kb`, and `collections`.

### Result — matches the original experiment closely

| Runtime | wall (s) | vs. original | RSS (MB) | Compactions |
|---|---|---|---|---|
| `ocaml-5.5` | 23.36 | 23.50 | 70.0 | 0 |
| `ocaml-auto-compact` | 27.90 (+19.4%) | 28.11 (+19.6%) | 70.0 | 0 |
| `socaml` | 27.88 (+19.3%) | 27.93 (+18.9%) | 70.1 | 0 |
| `socaml-auto-compact` | 28.15 (+20.5%) | 28.16 (+19.8%) | 70.1 | 0 |

Regression reproduced cleanly, within run-to-run noise of the original. Since
`socaml` (no auto-compact) shows the same regression as `ocaml-auto-compact`
(no new compactor), neither feature alone explains it — something shared
across all three non-stock builds is responsible.

## 4. Set up investigation plan

Created `experiments/pplacer-gc-regression/` (this folder) with:

- **`plan-pplacer-gc-regression.md`** — full investigation plan. Seeded with
  the full GC-stat breakdown (not just wall/RSS): minor collections are
  *exactly* 9152 across all four runtimes; major collections 3557/3557/3561/3561
  (~0.1% diff); yet `gc_time` is up 23-26%. That reframes the question from
  "why does compaction hurt" to "what's on the per-slice hot path that got
  more expensive" — pointing at `should_compact_from_stw_single` (named in
  the original results.md) as prime suspect. Also recorded: build-flag parity
  across all 4 opam switches confirmed identical (`flambda=false`, same
  `ocamlopt_cflags`, `dune` 3.23.1) — ruling out a compiler-config confound.
  Confirmed all 4 `tests.exe` binaries are unstripped and expose
  `caml_major_collection_slice` / `caml_minor_collection` / `caml_compact_heap`
  symbols, enabling `perf probe` uprobe instrumentation without rebuilding.
  Five-phase plan: (1) rule out remaining non-GC confounds, (2) localize
  minor-vs-major time via perf probes, (3) targeted source diff per branch,
  (4) flamegraph diff fallback, (5) confirm + prototype fix.
- **`src/running/config/experiments/pplacer_gc_regression.yml`** — the
  isolated single-benchmark config, kept permanently this time (documents the
  `overrides:` vs. top-level merge gotcha inline as a comment).
- **`logs/turing-2026-07-13-Mon-230928/`** — moved the reproduction run here
  as the Phase 0 baseline (previously landed under
  `experiments/compactor-comparison/logs/` by default, since that's where
  the config used lives — relocated since this run is really about the
  pplacer investigation, not the 4-way compactor comparison).

## 5. Quick sanity check: bypass the harness entirely

Ran the four binaries directly via `/usr/bin/time`, no `running-ng`, no
`perf stat`/`olly` attach at all — just:

```bash
OCAMLRUNPARAM="e=25,d=2" ./benchmarks/pplacer/pplacer_testsuite-<runtime> 5
```

| Runtime | wall (s) | maxrss (MB) |
|---|---|---|
| `ocaml-5.5` | 23.37 | 122.0 |
| `ocaml-auto-compact` | 27.93 (+19.5%) | 122.2 |
| `socaml` | 27.77 (+18.8%) | 122.4 |
| `socaml-auto-compact` | 28.19 (+20.6%) | 121.9 |

Matches the instrumented numbers almost exactly. **Rules out the measurement
harness itself** (perf attach, olly ring buffer, SIGSTOP/SIGCONT dance) as a
source of the regression — it's real and reproduces at the raw-binary level.
